# Макет Android приложения Апеофеоз

> Статус документа: исторический сценарный мокап. Использовать для состава экранов и пользовательских потоков, но не как финальный visual source of truth. Актуальное направление стиля теперь задаёт `web/` и `docs/ui-reference/THEME_TOKENS.md`.

> **MVP:** вход только **регистрация + пароль** (без внешнего SSO). Смены уходят на сервер **только пакетами** (`sync/batch`), по очереди при наличии сети. Рабочих добавляем **только онлайн**. Создание пользователя админом не делаем — только саморегистрация.

- **Primary**: #1976D2 (Синий)
- **Secondary**: #FF6F00 (Оранжевый)
- **Background**: #F5F5F5 (Светло-серый)
- **Surface**: #FFFFFF (Белый)
- **Error**: #D32F2F (Красный)
- **Success**: #388E3C (Зеленый)

### 3. Главный экран прораба — список рабочих (WorkersListScreen)

Для прораба главный экран после логина — это **один список рабочих**, с которого он стартует/останавливает смены. Никаких отдельных экранов «начало смены/конец смены» в MVP нет — всё делается одним нажатием на карточке.

```
┌─────────────────────────────────┐
│  Мои рабочие          ⚙️        │
├─────────────────────────────────┤
│ 🔍 Поиск...                     │
├─────────────────────────────────┤
│                                 │
│  ┌────────────────────────────┐ │
│  │ 👷 Вы (бригадир)            │ │

│  │  (тап по карточке          │ │
│  │   начнёт смену)            │ │
│  └────────────────────────────┘ │
│                                 │
│  ┌────────────────────────────┐ │
│  │ 👷 Иван Петров             │ │
│  │    Строитель               │ │
│  │    🟢 Смена идёт · 2ч 15м  │ │
│  │  (тап по карточке          │ │
│  │   завершит смену)          │ │
│  └────────────────────────────┘ │
│                                 │
│  ┌────────────────────────────┐ │
│  │ 👷 Мария Сидорова          │ │
│  │    Маляр                    │ │
│  │    🔴 Не работает           │ │
│  │  (тап по карточке          │ │
│  │   начнёт смену)            │ │
│  └────────────────────────────┘ │
│                                 │
│  ┌────────────────────────────┐ │
│  │ 👷 Алексей Иванов          │ │
│  │    Плотник                  │ │
│  │    🔴 Не работает           │ │
│  │  (тап по карточке          │ │
│  │   начнёт смену)            │ │
│  └────────────────────────────┘ │
│                                 │
│                  ⊕ Добавить рабочего
└─────────────────────────────────┘
```

**Компоненты:**
- SearchBar для поиска рабочие по имени/должности.
- Список карточек рабочих:
  - статус смены: «🟢 Смена идёт · Xч Ym» или «🔴 Не работает»;
- если пользователь нажал завершение смены **без сети** и END_SESSION ещё не ушёл — локально сразу показываем «🔴 Не работает» (смена остановлена), чтобы можно было начать новую смену (например, после обеда) даже офлайн; повторный END для той же сессии не создаём;
  - первая карточка — это сам бригадир (`Вы (бригадир)`) и по ней работает та же логика тапов (START/END через события);
  - **основное действие по тапу на карточке**:
    - если нет активной сессии — тап стартует смену;
    - если сессия активна — тап завершает смену;
  - вторичное меню `⋯` (контекстное) с действиями:
    - «Забрать себе» / «Переназначить прорабу…» (онлайн‑операция, без офлайн‑батча);
    - «Открыть детали рабочего» (история смен).
- Кнопка «⊕ Добавить рабочего» (FAB или нижняя CTA) — ведёт на экран формы добавления рабочего.

## Сверка мокапов с архитектурой и пробелы

Актуальные договорённости — в **`BACKEND_ARCHITECTURE.md`** и **`MOBILE_ARCHITECTURE.md`**. Кратко:

### Зафиксировано в MVP

| Тема | Как в продукте |
|------|----------------|
| Вход | Только **пароль**: `register` + `login`. **Без внешнего SSO.** |
| Пользователи | Только **саморегистрация**; админ **не создаёт** учётки через `POST /users`. |
| Смены | **Только `POST /api/v1/sync/batch`**, очередь и порядок — **head-of-line**; отдельных REST start/stop смены **нет**. |
| Рабочие | **Только онлайн**; в батчи **не входят**; **редактирование** ФИО рабочего в MVP **не делаем** (только перенос `foreman_id` и `status` через `PATCH`). |
| Отчёт ADMIN | Один эндпоинт: **часы + эквивалент смен (8 ч)** по **каждому** `workers`, **включая бригадира** — `GET /api/v1/reports/hours-by-worker-previous-day`. |
| Последний админ | Backend: **409**, если пытаются лишить систему единственного `ADMIN` — иначе **некому** назначать роли и разблокировать пользователей (остаётся только правка в БД). В UI — понятное сообщение. |
| Токены | Access + refresh; при **401** — `POST /api/v1/auth/refresh` и повтор запроса (подробно в `BACKEND_ARCHITECTURE.md`). |

### Сценарии бригадира (чеклист)

| Сценарий | Есть в мокапах? | Заметка |
|----------|-----------------|---------|
| Логин / регистрация | ✅ Login + § 1b | |
| Список + «Вы (бригадир)» | ✅ WorkersListScreen | |
| Старт/стоп тапом | ✅ | Всегда события → очередь батчей → `sync/batch` |
| Синхронизация | ✅ SyncStatusScreen | Один механизм для офлайна и онлайна |
| Добавить рабочего | ✅ WorkerFormScreen | Только при сети |
| Перенести чужого к себе | ✅ Меню ⋯ | `PATCH`, онлайн |
| Детали, история | ✅ WorkerDetailScreen | Редактирование рабочего в MVP не показываем |
| JWT | ⚠️ | Interceptor + refresh — см. backend-док |
| 409 по батчу | ✅ Неуспешные пакеты | |

### Сценарии админа (чеклист)

| Сценарий | Есть в мокапах? | Заметка |
|----------|-----------------|---------|
| Отчёты | ✅ § 2.1 → `AdminReportsScreen` → один пункт → детализация | Часы и смены (÷8), все `workers` |

@Composable
fun SessionTimer(startTime: Long) {
    val duration = remember(startTime) {
        derivedStateOf {
            System.currentTimeMillis() - startTime
        }
    }
    
    LaunchedEffect(Unit) {
        while (true) {
            delay(1000)
        }
    }
    
    Text(
        text = formatDuration(duration.value),
        style = MaterialTheme.typography.headlineMedium,
        color = MaterialTheme.colorScheme.primary
    )
}
