> **Актуальный сквозной план** (Docker на VM, test/prod, Android + backend): см. **[IMPLEMENTATION_DEPLOYMENT_PLAN.md](./IMPLEMENTATION_DEPLOYMENT_PLAN.md)**.  
> Ниже — детальный чеклист по мобильному клиенту; пути API вида `/api/auth/...` заменить на **`/api/v1/...`** согласно `BACKEND_ARCHITECTURE.md`.

## Резюме архитектуры

### Ключевые компоненты

1. **Android приложение (Kotlin + Jetpack Compose)**
   - Локальная БД: Room Database
   - Офлайн-режим: все операции работают без интернета
   - Синхронизация: автоматическая при появлении интернета
   - UI: Material Design 3, Jetpack Compose

2. **Backend API (Kotlin + Ktor)**
   - REST API для мобильного приложения
   - База данных: PostgreSQL (рекомендуется) или SQLite
   - Авторизация: JWT токены

### Офлайн-режим

- **Локальное кэширование**: Room Database на устройстве
- **Очередь операций**: операции сохраняются с `syncStatus = PENDING`
- **Автосинхронизация**: WorkManager запускает синхронизацию при появлении интернета
- **Конфликт-резолюшн**: обработка ошибок при синхронизации

## Технические детали

### Синхронизация данных

**Стратегия:**
1. Все операции сначала сохраняются локально
2. При наличии интернета - отправка на сервер
3. Сервер возвращает реальные ID
4. Локальная БД обновляется с серверными данными

**Обработка конфликтов:**
- Если сервер вернул ошибку (дубликат, невалидные данные)
- Локальная запись помечается как `ERROR`
- Пользователь получает уведомление
- Возможность повторить синхронизацию вручную

### Безопасность

- JWT токены с refresh token
- HTTPS для всех запросов
- Certificate pinning (опционально)
- Хранение токенов в EncryptedSharedPreferences
- Валидация данных на клиенте и сервере

### Производительность

- Lazy loading для списков
- Пагинация на сервере
- Кэширование часто используемых данных
- Оптимистичные обновления UI
- Background sync только при наличии Wi-Fi (опционально)

## Вопросы для обсуждения

> **Зафиксировано в MVP** (см. `BACKEND_ARCHITECTURE.md`): саморегистрация по паролю, без внешнего SSO; смены только батчами; один отчёт админа — часы и эквивалент смен (8 ч) за вчера по всем workers.

1. **Авторизация:**
   - ~~Как пользователи будут регистрироваться?~~ → **Саморегистрация** в приложении; админ не создаёт учётки через API.

2. **Роли:**
   - Какие роли будут в мобильном приложении?
   - Может ли рабочий (worker) использовать приложение?

3. **Офлайн-режим:**
   - Как долго данные могут храниться офлайн?
   - Нужна ли индикация "старых" данных?

4. **Отчеты:**
   - MVP: **просмотр** одного отчёта (часы + смены ÷8, включая бригадиров); экспорт в Excel — позже, если понадобится.

5. **Уведомления:**
   - Нужны ли push-уведомления?
   - О чем уведомлять? (завершение смены, синхронизация и т.д.)
