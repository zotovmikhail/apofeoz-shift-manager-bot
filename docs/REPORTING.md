# Отчёты и табель

## Таймзона

Все границы **календарных дней** в отчётах задаются **таймзоной из конфигурации сервера** (`app.reportTimeZone` / `REPORT_TIME_ZONE`). **По умолчанию в проекте — `Europe/Moscow`**: смены и часы по дням считаются по московскому времени (в т.ч. полночь при разбивке длинной смены). Поля `from` / `to` в API — даты **в этой зоне** (локальные даты без времени).

## JSON-отчёты (агрегаты)

- **`GET /api/v1/reports/hours-by-worker-previous-day`** — сумма часов за один календарный день по всем работникам, которые либо сейчас **активны**, либо имеют закрытые смены в выбранный день.
- **`GET /api/v1/reports/hours-by-worker-range?from=&to=`** — то же за диапазон дат **включительно**.

**Норма смены** фиксирована **8 часов**. Поле `shiftEquivalent` = часы / 8, значение **округляется до 3 знаков после запятой** (и по строкам, и итог по сменам в JSON; то же в ячейках Excel-табеля).

Источник данных — только **закрытые** смены (`CLOSED` с заполненным `endAt`). Для диапазона и табеля учитывается именно пересечение смены с выбранным интервалом, а не только `endAt` внутри диапазона. Округление: длительность в секундах округляется до **минут**, затем переводится в часы.

## Табель Excel (`timesheet.xlsx`)

**`GET /api/v1/reports/timesheet.xlsx?from=&to=`** (только **ADMIN**) отдаёт файл `.xlsx` в разметке, созвучной учебному файлу «табель 2025»:

| Область | Содержимое |
|--------|------------|
| Колонки A–B | Пустые, под закрепление области (как в образце). |
| Колонка C | Строка 3 — «фамилия» / «дата»; ниже — **календарные даты** по одной на строку. |
| Пары колонок на работника | Слева — **доля смены** за день (часы за день / 8), если > 0; справа — **пусто** (резерв под будущие выплаты). |
| Строки 1–2 в образце | Формулы и деньги — **не генерируем**. |

### Раскладка смены по дням

Если смена пересекает полночь в таймзоне отчёта, **часы делятся по календарным суткам**: каждому дню начисляется только отрезок `[start, end)`, попадающий в этот день. Секунды по дню суммируются, затем для каждого дня отдельно применяется **округление до минут** и перевод в часы (как в JSON-отчётах по смыслу, но **по дню**).

### Ограничения текущей версии

- Нет колонок **выплат**, ставок и итоговых формул в шапке.
- В табель попадают все **активные** работники, а также работники с историческими закрытыми сменами в выбранном диапазоне.
- Диапазон дат не ограничен отдельно от API; при очень больших периодах разумно ограничить выбор на клиенте.

## JSON-табель для web / будущего редактирования

**`GET /api/v1/reports/timesheet?from=&to=`** (только **ADMIN**) возвращает ту же дневную матрицу, что используется для `timesheet.xlsx`, но в структурированном JSON:

- `workers[]` — список колонок работников в порядке вывода.
- `rows[]` — одна строка на календарную дату.
- `cells[]` внутри строки — одна ячейка на работника:
- `hours` — фактические часы за этот день.
- `shiftEquivalent` — доля смены (`hours / 8`) с округлением до 3 знаков.

Этот endpoint нужен для web-интерфейса и закладывает основу под будущие операции редактирования смен без обратного парсинга Excel.

## Клиент (Android)

На вкладке «Отчёт» доступны построение JSON-отчёта и **скачивание** `timesheet.xlsx` в каталог приложения (`Downloads` в sandbox), с тем же `from`/`to`, что введены для отчёта.
